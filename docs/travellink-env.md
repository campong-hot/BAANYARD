# Travel Link integration — env vars & runtime constraints

## Vars (see `.env.example`)

```
travellink_URL=https://www.travellink.go.th/dashboard/
travellink_API_KEY=
```

An uppercase mirror (`TRAVELLINK_URL` / `TRAVELLINK_API_KEY`) is also set in `.env`
for scripts/tooling that expect conventional uppercase env-var names. `.env` is
git-ignored; `.env.example` (no real values) is safe to commit.

`travellink_API_KEY` is intentionally **blank**. It has not been issued yet — fill
it in only when a real key exists, and never paste a real key into chat, code
comments, or committed files.

## Why the frontend can't just read `.env`

`web/` is a static site (see `Dockerfile` — plain `nginx:alpine` serving files,
no Node process). Static HTML/JS served to the browser has no access to
process env vars, and `.env` is never copied into the image. This is
deliberate: **an API key must never ship inside frontend JS**, since anyone
can view-source or open devtools and read it.

Current state of the Travel Link connector:

- `scripts/build-travellink.js` is a one-off, build-time Node script. It reads
  the local `trend_domestic.json` MOTS/CKAN dataset already in the repo and
  writes a static snapshot to `web/data/travellink-provinces.json`. It does
  **not** call `travellink_URL` or use an API key today — `travellink.go.th`
  itself blocks direct scraping (WAF), so the connector works from the same
  open dataset the dashboard is built on.
- The frontend (`web/js/features/travellink.js`, wired into `admin.js`) reads
  the static `web/data/travellink-provinces.json` snapshot at runtime via
  `fetch()` (same pattern as every other `web/data/*.json` file loaded in
  `app.js`). It does not call the Travel Link API directly and never touches
  `.env`.

## If/when a live API call is needed

Do not call `travellink_URL` with `travellink_API_KEY` from browser JS. Instead:

1. Add a small server-side proxy (a container/service that reads `.env` at
   process start — e.g. a tiny Node/Express or nginx+CGI shim) that holds the
   key server-side and exposes a same-origin endpoint the static frontend can
   fetch (no key ever reaches the browser).
2. In Docker, pass the key via `docker-compose.yml` `environment:` /
   `env_file: .env` to that proxy service only — never bake it into the
   static `nginx:alpine` image that serves `web/`.
3. Until that proxy exists, keep using the pre-built JSON snapshot
   (`web/data/travellink-provinces.json`) as the data source, regenerated by
   `node scripts/build-travellink.js` from the local dataset.

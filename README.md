# BAANYARD บ้านญาติ

**“อุษาคเนย์เป็นญาติกัน”**

BAANYARD เป็นแนวคิดแพลตฟอร์มที่เชื่อมโยงชุมชนชนบทกับคนเมืองและผู้มาเยือน ผ่านการท่องเที่ยววิถีชุมชน สินค้าและบริการท้องถิ่น เรื่องเล่า องค์ความรู้ และกิจกรรมที่ผู้คนมีส่วนร่วม เป้าหมายคือทำให้ความสัมพันธ์ไม่จบลงแค่การซื้อขาย แต่ต่อยอดเป็นความไว้วางใจ การเรียนรู้ และการแบ่งปันประโยชน์อย่างเป็นธรรม

เอกสารนี้รวบรวมสาระจากไฟล์ใน [`docs/`](docs/) ให้เป็นภาพรวมเดียว และชี้ไปยังเอกสารต้นทางสำหรับรายละเอียดเพิ่มเติม ตัวเลขทางธุรกิจ แผนงาน และแนวคิดผลิตภัณฑ์ที่ระบุไว้เป็นข้อเสนอหรือประมาณการจากเอกสาร ไม่ใช่ผลประกอบการหรือผลลัพธ์ที่ยืนยันแล้ว

## แนวคิดและคุณค่าหลัก

ชื่อ BAANYARD เชื่อมโยงแนวคิดสองส่วน:

- **Barn (โรงนา):** ความอุดมสมบูรณ์ แหล่งผลิตและเก็บรักษาอาหาร ตลอดจนภูมิปัญญาและพันธุกรรมท้องถิ่น
- **Yard (ลาน/พื้นที่พบปะ):** พื้นที่เปิดให้ชุมชน คนเมือง และผู้มาเยือนได้แลกเปลี่ยนสินค้า บริการ และความรู้ในฐานะ “ญาติ”

โครงการวางบทบาทแพลตฟอร์มเป็น **ตัวกลางเชิงความสัมพันธ์ (Relationship Facilitator)** ไม่ใช่เพียงตลาดออนไลน์ แนวคิด “ญาติ” ใช้เป็นกรอบสร้างความไว้วางใจและความรับผิดชอบร่วมกันระหว่างผู้ผลิต ผู้ให้บริการ ลูกค้า และพันธมิตร

ประเด็นทางวัฒนธรรมในเอกสาร เช่น ความเชื่อมโยงของผู้คนในอุษาคเนย์ สัญลักษณ์นาค และประวัติศาสตร์ท้องถิ่น เป็นกรอบเรื่องเล่าและแนวทางศึกษาต่อ ควรนำเสนอโดยเคารพความหลากหลาย และตรวจสอบหลักฐานก่อนอ้างเป็นข้อเท็จจริงทางประวัติศาสตร์หรือวิชาการ

### อัตลักษณ์แบรนด์

- สื่อถึงบ้าน ความอบอุ่น ความปลอดภัย ความเป็นธรรมชาติ ความน่าเชื่อถือ และการเชื่อมโยงผู้คน
- แนวทางโลโก้ที่เสนอใช้รูปทรงโรงนา เส้นสายนาค ปีกครุฑ และพื้นที่ว่างที่สื่อถึงเมล็ดข้าว หยดน้ำ หรือหัวใจ เพื่อให้จดจำง่ายและปรับใช้ได้ในหลายพื้นที่

## กลุ่มผู้ใช้และสิ่งที่แพลตฟอร์มเสนอ

| กลุ่ม | ความต้องการ | สิ่งที่ BAANYARD มุ่งเสนอ |
| --- | --- | --- |
| คนเมืองและผู้มาเยือน | อาหารและสินค้าที่มีที่มา ประสบการณ์จริง การเรียนรู้ และความสัมพันธ์กับชุมชน | เรื่องราวผู้ผลิต ข้อมูลที่มาสินค้า กิจกรรมและการท่องเที่ยวชุมชน |
| ชุมชนและผู้ผลิต | ช่องทางตลาด การสื่อสารเรื่องราว การพัฒนาสินค้า และการแบ่งปันรายได้อย่างโปร่งใส | ตลาดสินค้า/บริการ เครื่องมือประชาสัมพันธ์ การจอง และระบบติดตามรายได้ |
| เจ้าบ้านและผู้จัดกิจกรรม | การนำเสนอที่พัก กิจกรรม ราคา และช่วงเวลาที่ให้บริการ | เครื่องมือจัดการข้อเสนอ การสื่อสารกับผู้มาเยือน และการจัดการข้อมูลเบื้องต้น |
| ผู้ดูแลระบบและพันธมิตร | ภาพรวมการดำเนินงาน มาตรฐาน ข้อมูล และการประสานงานหลายระดับ | แผงควบคุม รายงาน การตั้งค่า และแนวคิดการเชื่อมข้อมูลระหว่างสาขา/ส่วนกลาง |

เอกสารแผนธุรกิจวางภาพแพลตฟอร์มเป็น “Third Place” ที่รวมคลังสินค้า/ตลาดชุมชน (Barnyard) พื้นที่ชุมชนและเนื้อหา (Baan-Yat) และเวิร์กช็อปหรือประสบการณ์ในพื้นที่เข้าด้วยกัน ความแตกต่างที่ต้องการคือการเพิ่มคุณค่าของผู้ผลิตและชุมชน ไม่ได้จำกัดอยู่ที่การขายสินค้าเกษตรหรือสินค้า Organic

## พื้นที่นำร่องและประสบการณ์ชุมชน

เอกสารเสนอเริ่มต้นจาก **อำเภอศรีสงคราม จังหวัดสกลนคร และลุ่มน้ำสงคราม** ก่อนพิจารณาขยายไปยังลุ่มน้ำมูลและลุ่มน้ำโขง

แนวคิดกิจกรรมในพื้นที่นำร่องประกอบด้วย:

- โฮมสเตย์ที่รักษาเอกลักษณ์ท้องถิ่น พร้อมพัฒนาการต้อนรับและความสะอาด
- เรียนรู้การย้อมคราม ตั้งแต่การเก็บคราม การหมัก ไปจนถึงการย้อม
- เรียนรู้การทอผ้าและงานหัตถกรรม
- ทำอาหารพื้นบ้านจากวัตถุดิบในพื้นที่
- เดินป่าและเรียนรู้ธรรมชาติ/ทรัพยากรในชุมชน
- เวิร์กช็อป กิจกรรมชุมชน และการท่องเที่ยวเชิงวัฒนธรรมที่ชุมชนเป็นผู้เล่าเรื่อง

แนวทางปฏิบัติที่เสนอคือให้ชุมชนร่วมกำหนดกิจกรรม ราคา และขีดความสามารถในการรองรับผู้มาเยือน บันทึกความต้องการและทรัพยากรของแต่ละครัวเรือนก่อนออกแบบบริการ และใช้เนื้อหาที่ชุมชนยินยอมให้เผยแพร่

## สินค้าและการตรวจสอบย้อนกลับ

### สินค้าต้นแบบที่เสนอ

- **ข้าวเขี้ยวนาค:** แนวคิดข้าวสีเข้มและเมล็ดเรียวยาวที่เชื่อมโยงกับอัตลักษณ์ลุ่มน้ำสงคราม เอกสารบางฉบับกล่าวถึงการผสมข้าวเหนียวดำกับบาสมาติ แต่ยังต้องยืนยันสถานะพันธุ์ การพัฒนาทางการเกษตร การรับรอง และข้อกล่าวอ้างด้านโภชนาการก่อนนำเสนอเป็นข้อเท็จจริง
- **หยดปิตินาคา:** แนวคิดผลิตภัณฑ์เครื่องดื่มจากข้าวก่ำแบบพรีเมียม ใช้เรื่องเล่าพื้นที่และงานหัตถกรรม เช่น เซรามิกบ้านเชียงเครือและผ้าย้อมคราม การผลิตและจำหน่ายเครื่องดื่มแอลกอฮอล์ต้องตรวจสอบใบอนุญาต มาตรฐาน และข้อกำหนดการโฆษณาที่เกี่ยวข้อง
- **ข้าวเขียวนาค:** เป็นแนวคิดชื่อ/เรื่องเล่าสำหรับผลิตภัณฑ์หรือผลผลิตตามฤดูกาล ไม่ใช่ชื่อพันธุ์ข้าวที่ได้รับการยืนยันในเอกสาร ควรตรวจสอบกับนักวิชาการและชุมชนก่อนใช้ในเชิงพาณิชย์
- สินค้าอื่นที่กล่าวถึง ได้แก่ ผ้าคราม อาหารพื้นบ้าน ผลผลิตธรรมชาติ และงานหัตถกรรม

แนวทางการขายที่เสนอคือใช้ **Pre-order** ในช่วงทดลอง เพื่อลดความเสี่ยงด้านสต็อก และสื่อสารคุณค่าของสินค้าโดยให้ความสำคัญกับผู้ผลิตและบริบทท้องถิ่น

### Digital Passport

แนวคิด Digital Passport ใช้ QR Code เฉพาะสินค้าเพื่อเปิดดูข้อมูลที่ตรวจสอบได้ เช่น:

- แหล่งผลิตและข้อมูลแปลง/ผู้ผลิต ตามระดับการเปิดเผยที่เจ้าของข้อมูลยินยอม
- วิธีการผลิต ระยะเวลา และแนวทางดูแล
- ผลตรวจคุณภาพหรือการรับรองจากห้องปฏิบัติการ/สถาบันที่เกี่ยวข้อง
- เรื่องราวของผู้ผลิตและผลกระทบต่อชุมชน

การระบุพิกัดหรือข้อมูลส่วนบุคคลควรทำโดยได้รับความยินยอมและคำนึงถึงความปลอดภัยของชุมชน

## ธรรมนูญญาติและเครือข่ายความร่วมมือ

**ธรรมนูญญาติ (Kinship Charter)** เป็นกรอบกติกากลางที่เอกสารเสนอให้ใช้กับสมาชิกและพันธมิตร โดยมีหลักการสำคัญ:

1. **ความเป็นธรรม:** แบ่งปันรายได้และผลประโยชน์กับชุมชนอย่างโปร่งใสและตกลงร่วมกัน
2. **ความปลอดภัยและคุณภาพ:** กำหนดมาตรฐานและกระบวนการตรวจสอบสินค้าตามประเภท
3. **ความยั่งยืน:** เคารพระบบนิเวศ ภูมิปัญญา และทรัพยากรพันธุกรรมท้องถิ่น
4. **การมีส่วนร่วม:** ชุมชนมีส่วนร่วมในการเลือกสมาชิก วางแผนการผลิต และตัดสินใจเรื่องการใช้เรื่องราว/ข้อมูลของตน

พันธมิตรที่เสนอและบทบาทเบื้องต้น:

| พันธมิตร | บทบาทที่เสนอ |
| --- | --- |
| มหาวิทยาลัย/ศูนย์วิจัย | วิจัยพันธุ์และผลิตภัณฑ์ ตรวจคุณภาพ ให้คำปรึกษาและรับรองทางวิชาการตามขอบเขตที่ทำได้ |
| ผู้นำและกลุ่มชุมชน | ร่วมกำหนดกติกา คัดเลือกผู้ผลิต วางแผนการผลิตและกิจกรรม และกำกับการแบ่งปันผลประโยชน์ |
| ศิลปิน/KOL/ผู้สื่อสาร | ช่วยเล่าเรื่องและเชื่อมชุมชนกับผู้ชม โดยเคารพข้อเท็จจริงและสิทธิของเจ้าของเรื่อง |
| ผู้ผลิต/OEM | สนับสนุนการผลิตตามกฎหมายและมาตรฐาน พร้อมรักษาคุณภาพและอัตลักษณ์ผลิตภัณฑ์ |
| ธุรกิจและผู้สนับสนุนท้องถิ่น | สนับสนุนเงินทุน เครือข่าย การตลาด หรือการบ่มเพาะกิจการชุมชน |

ข้อเสนอด้านการประสานงานคือเริ่มจากกิจกรรมหรือโครงการร่วมมือที่มีขอบเขตชัดเจน แทนการรอข้อตกลงกว้างที่ใช้เวลานาน และติดต่อหน่วยงานวิจัย/พัฒนาของมหาวิทยาลัยเพื่อหาผู้ทำงานเชิงพื้นที่

## รูปแบบรายได้และตัวเลขประมาณการ

### ช่องทางรายได้ที่ปรากฏในเอกสาร

- รายได้จากการจำหน่ายสินค้าโดยตรง
- ค่าธรรมเนียมจากธุรกรรมบนแพลตฟอร์ม
- ค่าจัดกิจกรรม เวิร์กช็อป และท่องเที่ยวเชิงวัฒนธรรม
- สมาชิกแบบรายปีและสิทธิพิเศษ
- โฆษณาหรือการสนับสนุนจากแบรนด์ที่เกี่ยวข้อง
- บริการให้คำปรึกษา/จัดการ เช่น โลจิสติกส์ การสร้างแบรนด์ และการตลาดให้ชุมชน

แผนธุรกิจใช้สมมติฐานค่าธรรมเนียม/GP **20% ของ GMV** ขณะที่เอกสารแนวคิดแพลตฟอร์มเสนอ Transaction Fee **10–15%** ตัวเลขเหล่านี้เป็นสมมติฐานคนละชุดและยังต้องพิจารณาต้นทุนจริง ข้อตกลงกับชุมชน ภาษี และความเหมาะสมของแต่ละประเภทสินค้า/บริการก่อนกำหนดราคา

### งบประมาณและเงินลงทุนที่เสนอในเอกสาร

- **ข้อเสนอเงินลงทุนในแผนธุรกิจ:** 1,500,000 บาท แบ่งเป็นพัฒนา MVP 800,000 บาท (3–6 เดือน), การตลาด/สร้างชุมชน 300,000 บาท (12 เดือน) และดำเนินงาน/ทุนหมุนเวียน 400,000 บาท
- **ข้อเสนอในร่างโครงการวิจัย:** ปรับปรุงโฮมสเตย์ 1,500,000 บาท, ฝึกอบรม 300,000 บาท, Mobile Application 800,000 บาท, การตลาด 400,000 บาท และกองทุนอนุรักษ์ 300,000 บาท รวมตามรายการ 3,300,000 บาท
- **ประมาณการระดมทรัพยากรในบันทึกกลยุทธ์:** ระยะต้นแบบ 0–6 เดือน 700,000–1,300,000 บาท และระยะขยายผล 6–18 เดือน 2,200,000–3,500,000 บาท

งบประมาณทั้งสามชุดมีขอบเขตและสมมติฐานต่างกัน ไม่ควรรวมเป็นงบเดียวโดยตรง ต้องจัดทำงบประมาณฉบับปัจจุบันและยืนยันต้นทุนกับชุมชน/ผู้ให้บริการก่อนเสนอแหล่งทุน

## แผนดำเนินงานและตัวชี้วัด

### แนวทางเริ่มต้น

1. สำรวจชุมชน ครัวเรือน อาชีพ ความต้องการ และทรัพยากรในพื้นที่
2. ประชุมร่วมกับชุมชนเพื่อกำหนดปัญหา ขอบเขตโครงการ และกติกาธรรมนูญญาติ
3. เลือกชุมชน/ผู้ผลิต/ที่พัก/กิจกรรมต้นแบบจำนวนน้อย และออกแบบ Business Model Canvas
4. ทดลองสินค้าและกิจกรรม พร้อมตรวจสอบคุณภาพ กฎหมาย และความพร้อมของการจัดส่ง
5. สร้างเนื้อหาและช่องทางดิจิทัล ใช้การจองหรือ Pre-order เพื่อทดลองอุปสงค์
6. เก็บข้อมูลผลลัพธ์ รับฟังข้อเสนอแนะจากชุมชนและลูกค้า แล้วปรับปรุงก่อนขยายผล

### Roadmap ที่เสนอ

- **ปีที่ 1:** จัดทำธรรมนูญญาติ ประสานมหาวิทยาลัย/ศูนย์วิจัย ทดลอง Digital Passport และเปิดตัวสินค้าหรือกิจกรรมหลักในตลาดคนเมือง
- **ปีที่ 2:** ประเมินผลและเตรียมขยายโมเดลสู่ลุ่มน้ำมูล/โขง พร้อมพัฒนาระบบดิจิทัลและมาตรฐานตามความพร้อม

### ตัวชี้วัดที่ควรติดตาม

- **เศรษฐกิจ:** รายได้ครัวเรือนสมาชิก โดยมีเป้าหมายเบื้องต้นเพิ่มขึ้นอย่างน้อย 20% ตามที่เอกสารเสนอ
- **สิ่งแวดล้อม/วัฒนธรรม:** การดูแลพื้นที่และการเพิ่ม/รักษาพันธุ์พืชพื้นเมืองหรือองค์ความรู้ท้องถิ่น
- **สังคมและตลาด:** สมาชิกที่ใช้งานจริง การซื้อซ้ำ การเข้าร่วมกิจกรรม และความพึงพอใจ
- **ความไว้วางใจ:** การเข้าดู Digital Passport ผลตรวจคุณภาพ และความเข้าใจของผู้ซื้อเกี่ยวกับที่มาสินค้า
- **การดำเนินงาน:** ความโปร่งใสในการแบ่งรายได้ คุณภาพบริการ และข้อร้องเรียน/ปัญหาที่ได้รับการแก้ไข

ค่าเป้าหมายต้องกำหนดนิยาม วิธีเก็บข้อมูล ช่วงเวลา และฐานเปรียบเทียบให้ชัดก่อนใช้ประเมินผล ห้ามนำตัวเลขเป้าหมายหรือค่าจำลองไปสื่อสารเป็นผลลัพธ์จริง

## แพลตฟอร์มดิจิทัลและขอบเขตของเดโม

เอกสารผลิตภัณฑ์ระบุประสบการณ์สำหรับสามบทบาทหลัก ได้แก่ **Guest, Host และ Admin** พร้อมส่วน Privacy และ Investor Pitch:

- **Guest:** เลือกภาษา ดูชุมชน/สินค้า/กิจกรรม อ่านเรื่องราว ดูข้อมูลผู้ให้บริการ แชต ตะกร้า และขั้นตอนชำระเงินจำลอง
- **Host:** เริ่มต้นสร้างข้อเสนอสินค้า/บริการด้วยขั้นตอนสั้น ๆ จัดการรายการ และตอบข้อความ
- **Admin:** เริ่มที่ผู้ดูแลระดับประเทศ (ประเทศไทย) มี Dashboard, Settings, Reports และการ Sync จำลอง พร้อมแนวคิดเจาะลงสาขา เช่น ศรีสงคราม และขึ้นไปยัง HQ
- **Privacy:** แสดงข้อมูลความยินยอมและแนวทางคำขอเข้าถึง/ลบข้อมูลในรูปแบบเดโม พร้อมระบุการปฏิบัติตามมาตรฐานเป็น Roadmap เท่านั้น
- **Investor Pitch:** นำเสนอปัญหา แนวคิด ผลิตภัณฑ์ โมเดลธุรกิจ การเติบโต และข้อเสนอเงินลงทุน โดยตัวเลขต้องติดป้าย **Estimate** หรือ **Simulated/Demo**

### เทคโนโลยีและขอบเขตปัจจุบัน

- แอปต้นฉบับสำหรับเดโมนักลงทุนอยู่ใน [`App/`](App/) ใช้ Vite, React และ TypeScript
- เวอร์ชัน static สำหรับโฮสต์ทั่วไปอยู่ใน [`web/`](web/) ใช้ HTML, CSS, JavaScript และ JSON ไม่ต้อง build ด้วย Node เพื่อเผยแพร่
- เดโมใช้ข้อมูลจำลอง การเข้าสู่ระบบ/ผู้ให้บริการ OAuth, การชำระเงิน, การแปลภาษา, การซิงก์ข้อมูล และ KPI ไม่ใช่บริการ production
- แนวคิดในเอกสารระบุให้รองรับภาษาในการสมัคร การแปลแชตจำลอง ผู้ให้บริการเข้าสู่ระบบที่ตั้งค่าได้ และประสบการณ์ใช้งานที่ลดขั้นตอน
- แผนงานเทคโนโลยีในเอกสารประชุมเคยกล่าวถึง Next.js และ Supabase ส่วนข้อกำหนดเว็บแอปนักลงทุนฉบับหลังเลือก Vite + React + TypeScript แบบ client-only ซึ่งเป็นขอบเขตของเดโมปัจจุบัน
- Flutter, หน้าจอ Splash/Login/Dashboard/Profile/Report และ API ที่กล่าวถึงในเอกสารเก่าเป็นแนวคิด/ตัวอย่างในอดีต ไม่ใช่สถาปัตยกรรมปัจจุบันของเดโมเว็บ
- PDPA, GDPR, ISO 27001, ISO 27701, SOC 2 และ Privacy by Design เป็นแนวทางพัฒนาหรือ Roadmap เท่านั้น **ไม่ได้รับรองว่าแพลตฟอร์มผ่านการรับรองหรือการตรวจประเมินแล้ว**

## Travel Link และการจัดการข้อมูลลับ

เอกสาร Travel Link ระบุสถานะปัจจุบันไว้ดังนี้:

- เว็บไซต์ `web/` เป็น static site ไม่มี Node server ที่ให้ browser อ่าน environment variables ได้
- ตัวเชื่อมต่อที่มีอยู่เป็นสคริปต์ build-time `scripts/build-travellink.js` ซึ่งสร้าง snapshot [`web/data/travellink-provinces.json`](web/data/travellink-provinces.json) จากข้อมูลเปิดใน repository
- Frontend โหลด snapshot JSON นั้น ไม่ได้เรียก Travel Link API โดยตรง
- ห้ามฝัง API key ใน JavaScript ฝั่ง browser, image หรือไฟล์ที่เผยแพร่สู่สาธารณะ
- หากต้องเรียก API จริง ให้เพิ่ม server-side proxy และส่ง key ให้เฉพาะ service ฝั่ง server ผ่าน environment/secret management
- `travellink_API_KEY` ในเอกสารตั้งใจเว้นว่างไว้จนกว่าจะได้รับ key จริง ห้ามใส่ค่าจริงใน source control หรือเอกสารสาธารณะ

เอกสาร Mobile App รุ่นเก่ากล่าวถึง API `http://api.campong.co.th` และ bearer token ในไฟล์ config ตัวอย่างนั้นไม่ควรนำไปใช้เป็นแนวทาง production โดยตรง หากเชื่อมต่อ API จริงให้ใช้ HTTPS จัดการ credential อย่างปลอดภัย และไม่เก็บ secret ในแอป client

## ข้อควรตรวจสอบก่อนนำไปใช้จริง

- ตรวจสอบข้อมูลพันธุ์ข้าว การรับรอง งานวิจัย และข้อกล่าวอ้างด้านคุณภาพ/โภชนาการกับหน่วยงานที่เกี่ยวข้อง
- ตรวจสอบใบอนุญาตและกฎหมายสำหรับเครื่องดื่มแอลกอฮอล์ การท่องเที่ยว โฮมสเตย์ อาหาร การขายออนไลน์ และการโฆษณา
- ตกลงราคา ค่าธรรมเนียม การคืนเงิน การส่งสินค้า และการแบ่งปันรายได้กับชุมชนเป็นลายลักษณ์อักษร
- ขอความยินยอมก่อนเผยแพร่เรื่องราว ภาพถ่าย วิดีโอ พิกัด หรือข้อมูลส่วนบุคคล และกำหนดผู้เข้าถึง/ระยะเวลาเก็บรักษา
- ตรวจสอบการเข้าถึงข้อมูล ความปลอดภัยของระบบ การสำรองข้อมูล และแผนรับมือเหตุละเมิดข้อมูลก่อนเปิดบริการจริง
- จัดทำตัวเลขทางการเงินและ KPI ฉบับเดียวที่ระบุสมมติฐาน แหล่งข้อมูล และรอบเวลาชัดเจน
- ตรวจสอบแนวคิดประวัติศาสตร์และวัฒนธรรมกับผู้รู้และชุมชน เพื่อหลีกเลี่ยงการเหมารวมอัตลักษณ์ของกลุ่มชาติพันธุ์
